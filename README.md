# 충청남도교육청 신·재생에너지 통합관리시스템

충청남도 관내 학교에 설치된 태양광 발전설비의 발전량과 설비 상태를 통합 관리하는 웹 프런트엔드입니다.
현재는 **목업 데이터**로 동작하며 백엔드 연동은 포함하지 않습니다.

## 실행

```bash
yarn install
yarn dev
```

`http://localhost:3100` 에서 열립니다. (3000번은 사내 다른 프런트엔드가 쓰고 있어 3100으로 잡았습니다.)

| 명령 | 설명 |
| --- | --- |
| `yarn dev` | 개발 서버 |
| `yarn build` | 타입체크(`tsc -b`) 후 프로덕션 빌드 |
| `yarn preview` | 빌드 결과 미리보기 |
| `yarn lint` | ESLint + Stylelint |
| `yarn lint:fix` | 자동 수정 |

## 기술 스택

React 19 · TypeScript(strict) · Vite · SCSS Modules · react-router-dom(createBrowserRouter) ·
Zustand · motion(framer-motion) · ECharts

포매터는 따로 두지 않고 ESLint flat config + `@stylistic` 으로 코드 스타일을 강제합니다
(작은따옴표 · 세미콜론 · 2-space · 후행 콤마 · import 정렬 · 3단계 이상 상대경로 금지).

### 발전 현황 — 계층 깊이에 따라 바뀌는 한 화면

메뉴를 나누지 않고 **고른 설비 계층에 따라 같은 화면이 다른 깊이를 보여 줍니다.**
발전소를 고르면 발전소 통계, 인버터를 고르면 인버터 통계가 됩니다.

```
충청남도 전체 → 발전소 → 인버터 → 스트링
```

화면 구성은 어느 깊이에서나 같습니다.

1. **조회 계층 경로** — `충청남도 전체 › 중앙초등학교 › 인버터 #1` 처럼 지금 위치를 보여 주고,
   앞 계층을 눌러 위로 올라갈 수 있습니다.
2. **발전정보 요약** — 설비용량 / 기간 발전량 / 기대 발전량 / 일사량 / 등가 발전시간 /
   조회 계층 / 최고 발전 시점 / 하위 설비 수.
3. **{하위 계층}별 발전** — 자식이 있을 때만 나옵니다. 제목이 계층에 따라 `발전소별 발전` ·
   `인버터별 발전` · `스트링별 발전` 로 바뀝니다.
   카드마다 **기준일 하루의 발전 곡선**을 넣어 종 모양이 무너진 설비가 바로 눈에 띄고
   (정상은 solar, 이상은 붉은 선), 카드를 누르면 그 설비로 한 단계 내려갑니다.
4. **시간대별 발전량** — 기준일 하루를 00시~23시로 편 막대 차트에 일사량 선을 겹칩니다.
5. **시점별 발전 데이터** — 차트/표 토글. 표는 지표가 행, 시점이 열인 전치형이고
   좌측 지표 열은 가로 스크롤에도 자리를 지킵니다.

시점 단위는 집계 단위를 한 단계 더 쪼갠 값입니다 — **일별 → 시간, 월별 → 일, 연도별 → 월**.

기대 발전량은 기간 합계를 그 시점의 **일사량 비율대로 나눠** 계산합니다. 햇빛이 많이 든 시점일수록
기대치도 높게 잡혀, 시점별로는 일사량 대비 실측이 얼마나 따라갔는지가 드러납니다.

인버터 아래 계층은 부모 건전도에 자기 상태만큼의 감산을 더 겹칩니다(`mocks/nodeStats.ts`).
정상 인버터에 물린 스트링 하나가 죽어 있는 상황이 부모 건전도만으로는 드러나지 않기 때문입니다.

### 수집데이터

15분 주기(하루 96건)로 들어오는 발전전력·일사량·직류전압·직류전류·모듈온도·계통전압을 다룹니다.
트렌드 차트는 측정 항목을 바꿔 가며 보고, 일사량을 겹쳐 볼 수 있으며, 96개 점을 다 펼치면 촘촘하므로
dataZoom 으로 구간을 좁힐 수 있습니다. **수집이 끊긴 구간은 선을 잇지 않아** 결측이 그대로 드러납니다.

### AI진단

점수 하나로 뭉뚱그리지 않고 **발전시간(h)·이용률(CF)** 두 지표를 축으로 삼습니다. 발전시간은 발전량을
설비용량으로 나눈 값이라 용량이 다른 설비도 그대로 견줄 수 있습니다. 각 패널은 기간 평균과 직전 기간 대비
변화, 일별 추이, 최고·최저일을 함께 보여 주고 기준선 아래로 떨어지면 색이 바뀝니다.
설비별 진단은 인버터 카드마다 상태 배지 · 고장코드 · 발전시간 추이 · 하위 스트링 상태를 담고, 고장코드를 누르면
짐작되는 원인과 조치 방법이 모달로 열립니다(`mocks/equipment.ts` 의 `FAULT_CODES`).

### 알림이력

기간·유형·심각도·조치여부·정렬로 걸러 표 또는 **타임라인**으로 봅니다. 타임라인은 알림이 열려 있던 구간을
시간축 막대로 그려, 표로는 잘 안 보이는 "같은 시기에 몰린 알림"을 드러냅니다. 아직 조치되지 않은 건은
사선 무늬로 오른쪽 끝까지 이어집니다.

## KRDS 에서 차용한 것

전자정부 디자인시스템(KRDS)에서 **레이아웃 규칙만** 가져오고 색·타이포·컴포넌트 비주얼은 자체 설계했습니다.

- 컨테이너 폭 1280px, 좌우 여백 데스크톱 40 / 태블릿 24 / 모바일 16px → `styles/utils/_mixins.scss` 의 `container` 믹스인
- 브레이크포인트 mobile ≤600px · tablet ≤900px · desktop ≥901px → `styles/utils/_media.scss`
- 홈이 아닌 페이지는 브레드크럼 + 좌측 컬럼 2단. 좌측 컬럼(268px)에는 하위 메뉴와 조회 대상 패널이
  함께 들어가고 본문을 따라 sticky 로 붙습니다. 900px 이하에서 하위 메뉴는 상단 가로 스크롤 탭이 됩니다
  → `layouts/SubPageLayout`, `components/layout/Lnb`

## 조회 대상 선택 — 설비 계층

홈을 뺀 모든 화면은 **좌측 컬럼의 조회 대상 패널**에서 대상을 고릅니다
(`components/plant/PlantScopePanel` — 하위 메뉴 바로 아래에 놓입니다). 두 단계로 나뉩니다.

- **발전소는 모달로** — 128개를 드롭다운에 담기 어려워 검색·시·군 필터가 있는 모달로 펼칩니다.
  각 행에서 주소 · 설비용량 · 발전소 상태 · 일사량계 상태를 함께 보여 줍니다(`components/plant/PlantPicker`).
- **그 아래는 구조 트리로** — 고른 발전소의 계층을 접고 펼치며 인버터 · 스트링
  어느 칸이든 눌러 조회 대상으로 삼습니다(`components/plant/PlantTree`). 상태를 색점으로,
  용량을 오른쪽에 함께 적어 어디가 문제인지 트리에서 바로 보입니다.

계층은 `mocks/tree.ts` 가 하나의 노드 그래프로 관리하고(`전체 → 발전소 → 인버터 → 스트링`),
선택 상태는 노드 id 하나로만 저장합니다(`stores/plantStore`, localStorage 유지).
화면은 `hooks/usePlantScope` 가 주는 `node` · `plant` · `inverter` · `factor`(설비용량 비율)로 반응하고,
발전소 단위까지만 다루는 화면은 `plantLabel` 을 씁니다.

요약은 같은 패널 안에서 계층에 맞춰 바뀝니다(`components/plant/PlantSummary`) — 스트링을 고르면
"스트링 상태 / 최말단 설비", 인버터를 고르면 "스트링 3" 처럼 하위 계층 이름이 따라옵니다.
900px 이하에서는 좌측 컬럼이 가로로 펴지면서 하위 메뉴는 스크롤 탭, 조회 대상 패널은 2단 그리드가 됩니다.

| 화면 | 조회 대상을 고르면 |
| --- | --- |
| 발전 현황 | 고른 계층 기준으로 요약·차트·표가 모두 바뀌고, 하위 계층 카드가 따라 바뀝니다 |
| 기간별 통계 | 발전량이 그 대상 몫으로 환산되고, 값의 크기에 맞춰 단위가 kWh ↔ MWh ↔ GWh 로 바뀝니다 |
| 학교별 비교 | 전체 순위는 그대로 두고, 선택한 학교 행을 강조합니다. 20위 밖이면 맨 아래에 붙여 비교할 수 있게 합니다 |
| 환경 기여도 | 저감량·소나무 환산이 그 발전소 몫으로 줄어듭니다 |
| 수집데이터 | 그 발전소의 계측값·수집 현황만 조회합니다. 인버터까지 고르면 발전전력·직류전류가 그 몫으로 줄어듭니다 |
| 진단 요약 | 그 설비의 이용률·상태·미조치 이상·점검 이행률로 진단 점수를 다시 계산합니다 |
| 설비별 진단 | 그 발전소에 달린 인버터만 보여 줍니다. 전체일 때는 이상 설비를 앞세웁니다 |
| 이상 이력 · 점검 일정 · 알림이력 | 그 발전소 건만 남기고, 없으면 빈 상태를 안내합니다 |

## 날짜 선택

달력은 이전·다음 버튼으로 한 달씩 넘기지 않고 **세로 스크롤로 여러 달을 한 번에 지나갑니다**
(`components/common/Calendar`). 열면 현재 선택된 달로 스크롤이 맞춰지고, 월 제목은 스크롤 중에도
상단에 붙어 지금 어디인지 알려 줍니다. 스크롤 스냅을 걸어 달 경계에 자연스럽게 멈춥니다.
일 단위 달력은 2024-01 ~ 2026-12(36개월), 월·연 단위는 2021 ~ 2026을 다룹니다.

- **발전통계 — DatePicker** (`components/common/DatePicker`): 집계 단위(일별/월별/연도별)에 따라
  일·월·연 중 하나를 고릅니다. 고른 날짜가 속한 구간을 그리고, 그 구간의 막대를 진하게 짚어 줍니다.
  단위를 바꾸면 달력도 날짜 격자 ↔ 월 격자 ↔ 연 목록으로 함께 바뀝니다.
- **진단 — DateRangePicker** (`components/common/DateRangePicker`): 시작일과 종료일을 차례로 눌러
  기간을 잡습니다. 최근 7일/30일/90일/1년 프리셋이 있고, 적용 전까지는 초안 상태로만 바뀝니다.
  검출 시각·점검 일자를 이 기간으로 걸러 설비 진단·이상 이력·점검 일정 세 탭이 함께 움직입니다.

두 값 모두 `stores/filterStore`에 담겨 탭을 옮겨도 유지됩니다.

## 디자인

- 팔레트 "볕과 하늘": paper `#F7F9FC` / ink `#0E1A2B` / brand `#0B57A4` / **solar `#F5A524`** / leaf `#12A67B`.
  solar 는 **발전·태양을 뜻할 때만** 씁니다. 장식용으로 쓰지 않습니다.
- 타이포: 본문·UI 는 Pretendard Variable, 수치·라벨은 Space Grotesk(tabular-nums). 둘 다 CDN 로드이며,
  운영 배포 시에는 `public/fonts` 로 self-host 하는 편이 좋습니다.
- 라이트/다크 두 테마를 `html[data-theme]` 로 전환합니다. 색은 전부 `styles/tokens/_semantic.scss` 의 CSS 변수를 통합니다.
- 시그니처: 홈 히어로의 **태양 궤적 그래프**(`pages/Home/components/SunArc.tsx`).
  점선 호는 오늘 해가 지나는 길, 막대는 그 시각의 실제 발전 출력입니다. 막대가 호에 닿으면 일사를 온전히 걷어들인 것이고,
  벌어진 만큼이 구름 등으로 놓친 몫입니다.
- 모션은 `layouts/Provider` 의 `<MotionConfig reducedMotion="user">` 가 일괄 관리합니다.
  OS 의 "동작 줄이기" 설정을 켜면 모든 진입 연출이 최종 상태로 즉시 렌더됩니다.

## 구조

```
src/
├── components/common/   Button, Card, Badge, StatCard, SegmentedControl, Select, Table,
│                        Skeleton, Sparkline, CountUp, Reveal, EChart, EmptyState, Icon
├── components/layout/   Header, Gnb, MobileDrawer, Lnb, Breadcrumb, Footer,
│                        ThemeToggle, SkipLink, Logo
├── components/plant/    PlantPicker(모달), PlantTree(계층 트리), PlantSummary, PlantScopePanel
├── layouts/             Provider, RootLayout, SubPageLayout
├── pages/               Home, Statistics, Collection, AiDiagnosis, Alerts
├── configs/navigation   GNB·LNB·브레드크럼이 공유하는 단일 내비게이션 정의
├── routes/              PATH 상수 + createBrowserRouter 라우트 트리
├── mocks/               충남 15개 시·군 기반 더미 데이터 (결정적 난수)
│                        tree(설비 계층) · nodeStats(계층별 실적) · equipment · generation
├── stores/              themeStore, plantStore(선택 노드), filterStore(날짜)
├── hooks/               usePlantScope, useCountUp, useChartPalette
├── interface/           도메인 타입
└── styles/              tokens · base · utils
```

컴포넌트는 `폴더/index.tsx` + `PascalCase.module.scss` 로 두고, 페이지는 default export,
공용 컴포넌트는 named export 를 씁니다.

## 실제 API 로 넘어갈 때

`src/mocks/*` 가 유일한 데이터 출처입니다. 각 페이지 컴포넌트는 이 모듈에서 값을 직접 읽고 있으니,
`src/service/` 와 React Query 훅을 추가하고 mocks 참조를 훅 호출로 바꾸면 됩니다.
타입은 `src/interface/energy.ts` 를 그대로 재사용할 수 있습니다.

## 접근성

건너뛰기 링크, 전역 `:focus-visible` 링, GNB·LNB `aria-current`, 표 `caption`/`scope`,
드로어 포커스 트랩과 ESC 닫기, 차트의 텍스트 요약(`EChart` 의 `summary`)을 갖췄습니다.
